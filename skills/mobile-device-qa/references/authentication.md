# 프로젝트별 인증

- Author: JunyoungJung
- Created: 2026-10-22
- Updated: 2026-10-29

로그인이 필요한 구간에서 [test-accounts](../../test-accounts/SKILL.md)를 사용한다. 정상 세션이 있으면 재사용하고, 계정이 필요하면 `find` 또는 `list` → `get` → 현재 기기·브라우저 도구로 입력 → 인증 후 화면 확인 순서로 진행한다. 계정 조회와 일반 입력에는 전용 helper·서명·runner·프로필·환경 선택 버튼이 필요하지 않다.

## 계정 저장과 사용

- 사용자가 현재 대화에서 알려 준 계정은 `register --credentials-stdin`으로 저장한다. 같은 값을 다시 입력하도록 요구하지 않는다. 갱신은 `update --credentials-stdin`을 사용한다.
- `get ALIAS`가 반환한 실제 아이디·비밀번호를 AI가 읽어 `fill`·`type`·`setValue` 등 현재 사용할 수 있는 입력 기능에 전달한다. 실기기·Simulator·Emulator·브라우저에 동일한 방식으로 적용한다.
- 환경·용도·기기 메타데이터는 알맞은 계정을 고르는 데 사용한다. 누락된 라벨이나 전용 도구의 제한을 계정 조회·사용 금지로 확대하지 않는다. 환경은 설치 빌드·설정·서버 응답 등 실제 근거로 확인하고, 확인되지 않은 환경 의존 항목은 미검증으로 남긴다.
- 실제 계정값을 답변·공유 보고서·버전 관리 파일에 반복하지 않는다. 계정 파일은 Mac의 기존 로컬 경로를 사용하며 플러그인에 포함하지 않는다.

## 로그인 후 작업 재개

한 입력 도구가 실패하면 다른 사용 가능한 입력 도구로 전환한다. 전용 입력기의 `cleanup`·프로필·서명 오류를 전체 QA 중단 조건으로 사용하지 않는다. 사용자 직접 입력 중에도 화면 확인·캡처·녹화를 일괄 금지하지 않고 현재 상태를 보며 이어간다.

추가 인증·CAPTCHA처럼 사용자 조작이 실제로 필요한 단계만 요청하고 독립 작업은 계속한다. 제출 결과가 불명확하면 화면과 세션을 먼저 확인한다. 로그인 버튼 수락과 인증 성공은 구분하며, 인증 후 화면이나 서버 응답을 확인한 뒤 원래 QA를 계속한다. 서버의 인증 거부를 무한 재시도로 해결하지 않는다.

기존 자료를 잃는 로그아웃·계정 전환·기기 등록 해제는 요청 범위와 보존 조건을 확인한다. 계정 저장은 서버 계정 생성이나 비밀번호 변경을 수행하지 않는다.
