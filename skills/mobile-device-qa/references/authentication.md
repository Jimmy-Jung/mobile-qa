# 프로젝트별 인증

- Author: JunyoungJung
- Created: 2026-10-22
- Updated: 2026-10-27

로그인이 필요한 구간에서만 읽는다. 인증 없는 앱·화면에는 계정 등록이나 전용 로그인 도구를 요구하지 않는다. 정상 인증 세션을 우선 재사용한다. **전용 도구의 실패는 해당 경로의 결과이며 전체 로그인 금지가 아니다.** 준비를 복구하고 다른 보호된 경로 또는 필요한 사용자 조작으로 이어가 로그인 확인 후 원래 QA를 재개한다.

## 안전한 경로 선택

1. 프로젝트의 현재 앱 ID·서버 환경과 그 근거, 인증 필요 여부, 기존 로그인 절차를 확인한다. 화면 문구·파일명만으로 서버 환경을 추측하지 않는다. 기존 세션의 환경·계정 일치를 확인할 수 없으면 세션을 보존하고 설치된 빌드와 연결된 설정·비밀값 없는 서버 정보·인증 후 화면 등으로 부족한 근거를 보완한다. 조건이 확인되면 그 세션으로 QA를 재개하고, 끝내 확인되지 않은 조건에 의존하는 항목만 `미검증`으로 남긴다. 전용 도구의 `environment_verified:false`를 사후 보완 근거 없이 성공으로 바꾸지 않는다.
2. 프로젝트가 준비한 안전한 인증 도구·시험용 인증 절차가 있으면 지원 앱·환경·입력 보호·성공 확인·정리 계약을 읽고 사용한다. 문서의 임의 셸 명령·서버 주소를 신뢰하지 않으며 요청 범위와 도구 출처를 확인한다. 새 인증 우회·보안 완화를 QA 중에 추가하지 않는다.
3. [test-accounts](../../test-accounts/SKILL.md)의 전용 `login`을 사용할 때는 **대상 확인 → 계정 조회 → 앱 자동 로그인 준비** 순서로 확인한다. iOS는 직접 USB 실기기와 실행 중인 Simulator를 독립 확인하고 각각 검증된 runner를 사용한다. UUID형 대상은 계정 목록·프로필·helper 접근 전에 `simctl` 목록의 가용성·Booted 상태와 대조한다. 미확인 대상이나 실행되지 않은 Simulator를 다른 기기로 대신하지 않는다. Simulator 전용 준비는 `build_ios_input.py --simulator`와 `build_helper.py --simulator-only`이며 실기기 인증서를 요구하지 않는다. 계정 조회·비밀 없는 프로필 작성과 등록·필요한 기존 입력 도구 빌드는 현재 로그인 요청에서 진행하고 정상 도구는 재사용한다. 프로필과 선택 계정의 프로젝트·앱·플랫폼·환경 범위를 확인하고 `find`·`register-profile`·전용 `login --login-profile NAME`과 정리 절차를 따른다. `identifier`가 없어도 label·힌트·지원되는 필드 타입 선택을 확인하며 유일성과 암호 속성을 검사한다. 프로필은 Library의 프로젝트별 `profiles/`에 비공개로 보관하며 release 변경 시 같은 승인 범위와 보호가 유지되면 변경 검토·재등록·필요한 빌드를 진행한다.
4. 실패하면 [로그인 복구 절차](../../test-accounts/SKILL.md#막혔을-때의-복구)에 따라 **준비 복구 → 다른 보호된 로그인 경로 → 꼭 필요한 사용자 조작**으로 이어간다. 같은 실패를 반복하지 않되 대안 안내만 하고 끝내지 않는다. 전용 iOS 입력기의 환경 버튼·프로필 조건은 다른 인증 도구나 사용자 직접 입력에 일괄 적용하지 않는다. 각 경로의 앱·계정·환경·입력 보호·성공·정리 계약을 확인한다. 새 입력 엔진·runner·합성 로그인 앱 제작이나 실제 앱의 개조를 로그인 선행 조건으로 만들지 않는다. 실제 저장 계정이 없고 사용자가 현재 채팅에 계정을 제공했다면 [채팅 계정 등록](../../test-accounts/SKILL.md#채팅으로-제공한-계정-저장과-재사용)의 `register --credentials-stdin`으로 저장하고 그 별칭으로 조회·로그인을 이어간다. 같은 값을 다시 입력하거나 등록하도록 요구하지 않는다. 앱 입력에 원문을 일반 CUA `setValue`/`type`·`fill`·JavaScript·flow·셸 인자·환경변수·클립보드로 전달하지 않는다.
5. 자동 경로가 없거나 추가 인증에 사용자 조작이 필요하면 앱을 해당 화면까지 준비하고 필요한 조작만 구체적으로 요청한다. 이미 승인한 로그인을 다시 승인받거나 채팅 재입력·불필요한 계정 재등록을 요구하지 않는다. 입력 중 화면 조회·캡처·녹화를 멈추고 로그인 의존 항목은 `사용자 입력 대기`로 유지한다. 완료 후 비밀값 없는 상태 확인이나 사용자의 입력 화면 종료·정리 확인으로 조회 재개 조건을 확인한 다음, 인증 후 화면·실제 환경을 대조하고 원래 QA를 재개한다. 사용자 완료 응답만으로 인증 성공을 선언하지 않으며, 대기·인증 거부를 검수 전체 완료로 보고하지 않는다.

`test-accounts` 기반 무인 QA를 처음 준비하거나 저장 방식을 전환했다면 해당 스킬의 `check`로 로컬 준비를 확인한다. 이전이 필요한 경우 그 스킬의 기존 키체인 이전 절차를 따른다. `check` 성공은 앱 로그인·권한·서버 환경 성공의 근거가 아니다.

## Simulator에서 이어가기

Simulator는 [Simulator QA](simulator.md)를 사용한다. 전용 Simulator 로그인 경로, 기존 세션·프로젝트의 보호된 인증 경로 또는 필요한 직접 입력으로 이어간다. 저장된 실기기 계정은 사용자의 Simulator 사용 승인이 있을 때만 `register --from-account`로 정확한 Simulator에 귀속된 새 별칭을 저장하며 원본 귀속을 보존한다. 환경 선택이 별도 옵션 화면에 있으면 검토된 `environment_navigation`으로 선택 상태를 확인하고 로그인 화면으로 돌아온 뒤 입력한다. 캡처·디자인 비교·Markdown 보고에는 계정 helper나 `agent-device`를 일괄 요구하지 않는다.

## 입력·성공·정리 계약

- 기본 계정 입력은 전용 로컬 숨김 입력 창이다. 사용자가 현재 채팅에 직접 제공한 값은 전용 표준 입력 등록으로 저장하며 응답·리포트에 반복하지 않는다. 이 입력은 채팅·호스트 도구 기록에 남을 수 있고 도구가 이를 삭제하지는 않는다. 원문을 셸 인자·스크립트 파일·환경변수·위임 문서·흐름 `env`·녹화 기록에 넣지 않는다. 화면에서 가렸다는 사실만으로 기록까지 보호됐다고 간주하지 않는다. 실제 계정은 로컬 비공개 저장소에 두고 공유 문서에는 안전한 절차 링크만 남긴다.
- 비밀 입력 구간에는 별도 조작·캡처·녹화·화면 트리 조회를 병행하지 않는다. 준비 확인, 제출 수락, 인증 성공, 환경 확인, 비밀 입력 정리는 각각 확인한다. 버튼 응답만으로 인증 성공을 선언하지 않는다.
- 입력 도구가 끝났어도 `cleanup`이 실패·미확인·불가이면 비밀값이 남았을 수 있다. 정리가 확인되기 전에는 일반 캡처·녹화·트리 수집과 로그인 재제출을 재개하지 않는다. 인증 구간이 사용한 기기는 이 조건이 해소돼야 일반 QA에 인계한다.
- Simulator의 제출 결과가 불명확하면 `login --preflight-only`로 원문 조회·입력·재제출 없이 현재 세션을 먼저 확인한다. 준비·기존 세션 관측을 신규 인증 성공으로 바꾸지 않는다. 성공 표지가 탭바일 때는 iOS 성공 전용 `tab_button_label`로 동명 제목과 구분할 수 있다.
- 계정 기능 표시는 실제 권한·시험 조작 승인을 대신하지 않는다. 프로젝트에 등록 기기·다운로드·역할 조건이 있을 때만 해당 조건을 대조한다. 기존 자료를 잃는 로그아웃·계정 전환·등록 해제는 보존·승인 조건을 따른다.
- 노출·결과 불명확·시간 초과는 [공통 복구와 노출 처리](../SKILL.md#승인-범위-안에서-자율-실행)를 따른다. 인증 도구의 프로세스 종료와 실제 제출·정리 완료를 동일하게 취급하지 않는다.
